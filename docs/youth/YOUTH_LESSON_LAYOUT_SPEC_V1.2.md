# 架構師指令 V1.2｜單課頁面「對標空天小匠排版」＋直式手機線性推進

> 來源：另一個 Claude 工作階段（自稱架構師）於 2026-11-20 傳來，全文照存。
> 發給：負責寫程式的 Claude Code（青少年無人機課程開發）
> 發出：架構師
> 優先級：本指令**高於** V1.0 與 V1.1 中關於單元頁版面、單元流程的部分；其他部分（範圍、資料、安全、不改既有系統）照 V1.1（下一則訊息）。
> 依據：使用者提供的對標截圖（空天小匠「第三人稱飛行操控基礎／基礎懸停訓練」電腦版課堂頁）與我們目前手機版兩張截圖（U01 認識無人機）。

---

## 0. 使用者的決定（不可擅自更改）

1. **版面與操作流程嚴格對標空天小匠**的單課頁：左側「本課學習路徑」4 步、中間大標題＋3D 演示＋階段時間軸＋播放控制、右側「當前動作」與「觀察與站位」資訊卡、頂部課程標題與「全屏授課」。不得自行改版、不得加入對標畫面沒有的大區塊。
2. **一節一節往下推進**：學生不是在步驟之間自己挑選，而是「下一步 → 下一步」。步驟列只用來**顯示進度**，未到的步驟不能點。
3. **以直式手機為主**：電腦版照對標排版；手機直式把同樣的區塊**依原順序上下堆疊**，不可改內容邏輯。

**只對標版面、流程與互動方式，不複製對方的品牌**：不得使用「空天小匠」名稱、Logo、吉祥物、圖片、3D 模型、文字教材或字型檔。我們用 FDE-AI 品牌、自己的 3D 模型與自己的教材。

## 2. 每一課的固定 4 步（嚴格照對標的內容邏輯）

對標頁的 4 步是：**01 訓練任務 → 02 三維演示 → 03 考核標準 → 04 訓練技巧**。全部 12 單元一律用這 4 步，**取代 V1.1 的「六段式」與目前手機版的「01 知識講解／02 互動操作／03 3D 實驗／…」五步**。

| 步驟 | 名稱與副標 | 內容 | 完成條件（才能按「下一步」） |
|---|---|---|---|
| 01 | **訓練任務**｜了解今天練什麼 | 本課目標 3 條、要用到的名詞（知識卡 3–5 張，每張 ≤120 字） | 知識卡全部翻閱過 |
| 02 | **三維演示**｜看清每一步怎麼做 | 3D 演示＋階段時間軸＋播放列＋右側「當前動作」「觀察與站位」 | 演示播放到結尾一次（可用倍速） |
| 03 | **考核標準**｜明確怎樣才算達標 | 列出達標數據（例：高度 1.35–1.65 m、水平偏離 ≤ 15 cm、懸停 3 分鐘）＋**隨堂測驗**（5 題，用達標標準出題） | 測驗作答完成（分數記錄；≥60 分顯示通過，未達可重做） |
| 04 | **訓練技巧**｜掌握做好的小竅門 | 3–5 條技巧＋常見錯誤；底部「開始實作」→ 進入對應的模擬練習或 3D 實驗任務 | 完成實作任務，或按「本課完成」 |
| 結束 | 本課完成頁 | 本課成績（測驗、實作）、總結卡口訣、**「下一課：Uxx 名稱 →」大按鈕** | — |

各課 02 三維演示的「階段時間軸」對應表：

| 單元 | 02 演示階段（時間軸分段） |
|---|---|
| U01 認識無人機 | 01 整機 → 02 機架 → 03 動力 → 04 飛控 → 05 電池 |
| U02 飛行安全 | 01 飛前檢查 → 02 場地判斷 → 03 站位 → 04 失控處理 → 05 收機 |
| U03 飛行科學 | 01 重力 → 02 推力 → 03 推力＝重力（懸停）→ 04 推力>重力（上升）→ 05 阻力 |
| U04 動力系統 | 01 拆電機 → 02 定子轉子 → 03 換相 → 04 反扭力 → 05 正反槳 |
| U05 電池科學 | 01 單顆電芯 → 02 串聯 3S → 03 並聯 2P → 04 4S/6S → 05 安全存放 |
| U06 飛行姿態 | 01 油門 → 02 俯仰 → 03 橫滾 → 04 偏航 → 05 組合 |
| U07 飛控與感測器 | 01 陀螺儀 → 02 加速度計 → 03 氣壓計 → 04 GPS／羅盤 → 05 回饋穩定 |
| U08 組裝 | 01 機架 → 02 電機 → 03 ESC → 04 飛控／接收機 → 05 GPS／檢查 |
| U09 基礎飛行 | 01 解鎖 → 02 起飛 → 03 懸停 → 04 下降 → 05 上鎖（**直接照對標頁**，含第三人稱學生站位） |
| U10 程式設計 | 01 順序 → 02 迴圈 → 03 條件 → 04 執行航線 → 05 除錯 |
| U11 無人機足球 | 01 球場 → 02 足球機 → 03 進攻路線 → 04 防守站位 → 05 射門 |
| U12 STEM 專題 | 01 提問 → 02 假設 → 03 實驗 → 04 紀錄 → 05 發表 |

U09 必須做出對標頁的**第三人稱站位場景**：學生人物（身高標籤）站在機尾後方、手持遙控器面向飛機；起降墊有橙色起降參考線、藍色懸停容差框；無人機有機頭標記（黑色鏡頭）。站位數據（身高、距離）與達標範圍做成內容檔參數，由教師核對後填正式值。

## 3. 直式手機版（主要使用情境）

原則：**同一套區塊、同一個順序、上下堆疊**；不新增區塊、不改文字邏輯。

```
┌──────────────────────────┐
│ ← 返回   U09 基礎飛行  [全屏] │  ← 精簡頂部列（課程頁內隱藏站內導航）
│ 基礎飛行 / 基礎懸停訓練       │
├──────────────────────────┤
│ ① ─ ② ─ ③ ─ ④   02 / 04    │  ← 學習路徑改橫向步驟條：4 格平均分寬，不可左右捲動
│ 任務 演示 標準 技巧            │     完成=打勾、目前=藍底、未到=灰色鎖，不可點未到的步驟
├──────────────────────────┤
│ DEMONSTRATION / 三維演示      │
│ 看清起降動作，也看清學生站位   │  ← 大標題
├──────────────────────────┤
│ [三維][俯視][側視][機頭][復位] │  ← 視角分頁，可橫向捲動
│      3D 場景（4:3）          │  ← HUD 疊在右上
│ 單指旋轉・雙指縮放            │  ← 操作提示改成觸控用語
├──────────────────────────┤
│ 解鎖│起飛│懸停│下降│上鎖      │  ← 階段時間軸，5 格平均分寬
│ [▶] [↺] ━━━●━━ 1:16/3:14 [6×]│  ← 播放列
├──────────────────────────┤
│ 當前動作卡                   │  ← 原右側兩張卡移到下方，順序不變
│ 觀察與站位卡                 │
├──────────────────────────┤
│ 本課總結卡（先看懂，再起飛）   │
└──────────────────────────┘
│ [上一步]      [下一步 →]     │  ← 固定底部導航列（含安全區 padding），未達完成條件時「下一步」灰色並顯示原因
```

手機規則：
1. 課程頁內**隱藏站內主導航**（首頁／課程中心／虛擬實驗室／足球訓練／我的），只留「← 返回」。目前手機截圖中主導航被切掉（「我的」只剩一半）——課程外的頁面主導航必須改成**能完整顯示的寬度**（例如 4 項＋「更多」，或底部分頁列），不准出現被切掉的文字。
2. 步驟條 4 格**一定要在一個畫面內放下**（目前手機版是可左右滑的大卡片，「03 3D 實驗」被切掉，要改掉）。
3. 頂部列「學員登入」大按鈕在課程頁內改成小圖示，不擠掉課程標題。
4. 3D 區高度不超過畫面 45%，讓時間軸與播放列在第一屏就看得到。
5. 「全屏授課／全屏實驗」在手機上進入橫向全螢幕：3D 區滿版，時間軸與播放列疊在底部。
6. 底部固定導航列不得擋住內容（內容底部預留同等高度）。
7. 字級：標題 ≥ 24px、內文 ≥ 16px、按鈕觸控區 ≥ 44×44px。

## 4. 線性推進規則（取代目前「學生自選」做法）

1. 每課只能從 01 開始；完成條件（第 2 節）達成後「下一步」才可按。
2. 已完成的步驟可以回看（點步驟條或「上一步」），**未到的步驟不能點**。
3. 第 04 步完成 → 本課完成頁 → 「下一課」按鈕。課程中心的單元列表也依序解鎖：上一課完成才解鎖下一課（U02 飛行安全是足球訓練與所有操作實驗的前置條件）。
4. 進度存檔：離開再回來，直接回到上次的步驟與時間軸位置。
5. 教師模式（全屏授課）可自由切換步驟與階段，不受鎖定限制。
6. 測驗不及格不鎖死：可重做，記錄次數與最高分。

## 6. 內容檔格式調整（配合 4 步）

在單元資料檔加入以下欄位（舊欄位保留，知識卡移入 `steps.task.cards`）：

```js
steps: {
  task:   { title: '訓練任務', sub: '了解今天練什麼', objectives: ['…'], cards: [ /* 知識卡 */ ] },
  demo:   { title: '三維演示', sub: '看清每一步怎麼做', eyebrow: 'DEMONSTRATION', headline: '看清起降動作，也看清學生站位',
            scene: 'u09-hover', views: ['three','top','side','nose','reset'], durationSec: 194,
            phases: [ { key: 'arm', label: '解鎖', t: 0, action: { name: '解鎖', desc: '…', status: '電機怠速', timer: null } } /* … */ ],
            observe: { rows: [['身高','1.65 m'],['機尾後方','1.75 m']], legend: [['orange','起降參考線'],['blue','懸停容差區域']], pass: ['高度 1.35–1.65 m','水平偏離 ≤ 15 cm'] } },
  criteria: { title: '考核標準', sub: '明確怎樣才算達標', items: ['…'], quiz: [ /* 8 題題庫，抽 5 題 */ ] },
  tips:   { title: '訓練技巧', sub: '掌握做好的小竅門', tips: ['…'], mistakes: ['…'], practice: { lab: 'lab-xx', task: '…' } },
},
summary: { motto: '先看懂，再起飛', lines: ['觀察路線・理解要求', '分步練習・穩定控制'] },
next: 'unit-02',
```

站位距離、達標範圍等「待核對」數字一律放在內容檔，不寫死在程式裡；教師核對前內容檔標 `reviewedBy: ''`，頁尾顯示「教材審稿中」。

## 7. 執行順序與回報

1. **先做 U09 基礎飛行一課**（最接近對標頁，用來定版）：電腦版＋直式手機版都要完成 4 步線性推進、3D 演示時間軸與播放列、右側兩卡隨階段更新、第三人稱站位場景。
2. 交付截圖給使用者比對：電腦 1440×900、iPhone 13 直式、iPhone 13 橫式全屏，各截每一步（共約 15 張），**與對標截圖並排**。
3. 使用者確認版型後，再把 U01、U02、U04、U05 套用同一版型（V1.1 的 R1 範圍）。
4. 自動測試：Playwright 走完 U09 四步（未完成時「下一步」不可按、未到步驟不可點、重新整理後回到原步驟）、無 console error、手機無水平捲動、底部導航不擋內容。
5. 仍然遵守 V1.1：不改既有首頁與系統檔、不部署正式站、不送任何個資 POST、不呼叫外部 AI。

完成第 1、2 項後停下回報，等使用者確認版型。
