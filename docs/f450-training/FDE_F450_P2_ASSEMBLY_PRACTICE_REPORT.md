## 1. 做了什麼

### 1.1 共用資料模型 `f450-twin/training/model.js`

純資料與規則，不碰畫面；3D 組裝（P2）、2D 接線（P3）、判分（P5）都只讀寫它。

| 物件 | 內容 |
|---|---|
| 組裝單元 `ASSEMBLY` | 30 件，對應 GLB r8 全部 59 個節點；步驟取自 `parts-data.js` 的 `STEPS`（DJI 手冊順序） |
| 組裝狀態 | 每件：零件盤／拿在手上／已安裝／方向錯；另記錯誤紀錄 |
| 組裝規則 | 順序錯（前面步驟沒完成）、方向錯（Pixhawk、GPS 要對準機頭）、槳葉轉向錯（Quad X：右前、左後 CCW；左前、右後 CW）、位置錯 |
| 元件與接口 `COMPONENTS`／`PORTS` | 13 種元件、接口帶角色（電源輸入／輸出、訊號輸入／輸出、資料）與接頭類型；不提供腳位 |
| 正確接線 `EXPECTED_WIRES` | 20 條，每條指回 `WIRING` 的一列（14 列全用到） |
| 接線檢查 `validateWiring` | 缺線、接錯、極性錯、重複、同接口多線、接頭不合、方向錯、未知接口、自己接自己；每個問題都指回導線與元件 ID |

全部規則標 `REFERENCE`，`PRACTICE_ONLY = true`：未逐條對照教師實機照片前，只能練習，不計正式分數。

### 1.2 3D 組裝練習 `f450-twin/training/assembly-mode.js`

- 從 F450 頁下方實訓區「開始 3D 組裝練習」進入（也可用 `?mode=practice`）；上方五個模式按鈕不變。
- 學員在零件盤點零件拿起 → 在 3D 上把發藍光的零件拖到綠色圈 → 放開自動吸附（螢幕距離 46px，手機 64px）。
- 每一件都要學員自己拖；沒有自動完成、沒有「一鍵組好」。
- 錯誤即時提示：順序錯（拒絕拿起）、方向錯（裝上但發紅光，按「↻ 旋轉 90°」轉正）、槳葉轉向錯（拒絕安裝）。
- 進度條、錯誤次數、下一步提示、放回零件盤、重新開始。
- 藍色箭頭標示機頭；Pixhawk／GPS 的箭頭黃色＝沒對準、綠色＝對準。
- 結果不記錄、不計成績（P5／P6 才接判分與任務卡）。

## 3. 測試結果

### 單元測試：41／41 通過

```bash
node --test tests/f450-training/model.test.mjs
```

- 59 個 GLB 節點各屬一個組裝單元（含 three.js 把空白換底線的名稱）
- 照順序正確裝完 → 完成、0 錯誤
- 順序錯兩種（機臂太早、槳葉早於電池）、方向錯與轉正、不能旋轉的零件、槳葉轉向錯與換位、位置錯、沒拿起就安裝
- 20 條正確接線各一個測試（反向拉線也算對）；缺線、接錯、接頭不合、方向錯、極性錯、XT60 防呆、重複、同接口多線、未知接口、自己接自己

### 端對端：79／79 通過（headless Chromium，桌面 1440×1000、手機 390×844）

```bash
set PLAYWRIGHT_PATH=<playwright 路徑>
node tests/f450-training/practice_e2e.cjs <截圖資料夾>
```

- 桌面：用滑鼠把 30 件全部拖到位置，每件都確認「已安裝且看得到」；過程中故意犯 3 個錯（機臂太早、Pixhawk 沒轉正、CCW 槳拖到 CW 位置），都被正確抓到 → 完成 30/30、錯誤 3 次
- 四個槳位在螢幕上位置不同（防止零件疊在原點的假通過）
- 切回爆炸、整機、組裝流程、接線圖、尺寸五種模式，面板與 3D 正常；重新開始後歸零
- 手機：顯示練習面板、順序錯提示、拖曳下中心板安裝成功
- 兩種尺寸都沒有腳本錯誤

### 開發中發現並修好的問題

| 問題 | 原因 | 修正 |
|---|---|---|
| 零件全部「裝好」但畫面看不到 | three.js 載入時把節點名稱空白換成底線，比對不到 | 比對前換回空白；單元測試鎖住；端對端加「看得到」檢查 |
| 點零件盤後拖不到零件 | 零件盤在 3D 下方，點了頁面往下捲，3D 被捲出畫面 | 拿起零件後自動把 3D 捲回可見 |
| 遠側槳葉抓不到 | 拿起位置太高，被畫面上方的視角按鈕擋住 | 太靠近上緣就自動降低拿起高度 |

## 4. 風險

| 風險 | 程度 | 處理 |
|---|---|---|
| 規則依公開資料，可能與教師實機不同 | 中 | 全標 REFERENCE、只練習；等教師 Pixhawk 2.4.8 照片逐條核對 |

| `?practiceDebug=1` 測試接口 | 低 | 只回報座標與進度，不能改狀態；與既有 `?perf=1` 同類 |
