# F450 實訓中心 P3 報告：2D 接線畫布

- 日期：2026-11-14
- 分支：`feat/f450-assembly-training`（未推送、未發布）

## 1. 做了什麼

在 F450 頁下方實訓區新增「2D 接線練習」：

- 入口：實訓卡 A 的「開始 2D 接線練習 ↓」（也可用 `?wire2d=1`）。
- 原生 SVG 畫布，依無人機俯視方向擺放 16 個元件、40 個接口：Pixhawk 在中央，四角是 ESC 和馬達，下方是配電板、電源模組、電池，旁邊是接收機、GPS、安全開關、蜂鳴器。
- 接口顏色：紅＝電源、藍＝訊號、綠＝資料／周邊；接上的接口變實心。
- 操作：點一個接口，再點另一個接口就連線。點線可選取，選取後可以刪除或「紅黑對調」（模擬焊接時接反）。另有復原、全部清除。
- 鍵盤：Tab 移到接口、Enter 選取、Esc 取消、Delete 刪除選取的線。
- 「✓ 檢查接線」：用 P2 的 `validateWiring` 判斷；接對的線變綠、接錯的變紅。
  - 結果列出接錯、接頭不合、方向或類型錯、極性錯、重複、同接口多線，點列表可選取那條線。
  - 缺線先只顯示數量；要按「顯示缺少的線（提示）」才列出。
- 草稿只存在這台裝置的瀏覽器，重新整理後還在。
- 不依賴 3D／WebGL：不支援 3D 的裝置也能練習接線。
- 手機：畫布在自己的橫向捲動框內，頁面本身不會橫向捲動。
- 練習用：規則全部待實機核對，不提供腳位，結果不記錄、不計成績。

## 3. 測試結果

### 2D 接線端對端：29／29 通過（headless Chromium，桌面 1440×1000、手機 390×844 觸控）

```bash
set PLAYWRIGHT_PATH=<playwright 路徑>
node tests/f450-training/wiring_e2e.cjs <截圖資料夾>
```

- 入口按鈕顯示畫布；16 個元件、40 個接口
- 故意犯三種錯，都被抓到並標紅：
  - 右前 ESC 接到 MAIN OUT 2 → 接錯
  - XT60 接到 RC IN → 接頭不合
  - 焊盤紅黑對調 → 極性錯
- 缺線數正確；提示列出 20 條缺線
- 選取後刪除、復原、全部清除都正常
- 鍵盤也能連線
- 用滑鼠把 20 條正確接線全部接上（故意反方向拉線）→「全部 20 條都接對了」，20 條全綠
- 重新整理後 20 條草稿還在
- 3D 五種模式切換正常
- 手機：觸控連線成功，頁面沒有橫向捲動
- 兩種尺寸都沒有腳本錯誤

## 4. 風險

| 風險 | 程度 | 處理 |
|---|---|---|
| 規則依公開資料，可能與教師實機不同 | 中 | 全標 REFERENCE、只練習；等教師 Pixhawk 2.4.8 照片逐條核對 |
| 示意版面被誤認為實際腳位或位置 | 低 | 圖例與頁尾都寫「示意版面，不是實際尺寸與腳位」 |
| 手機上畫布要橫向捲動 | 低 | 畫布最小寬 720px，放在自己的捲動框；P7 實機測 |
| 「紅黑對調」是簡化模型（實際焊接時是兩條線） | 低 | 說明寫「模擬焊接時接反」；只有焊盤與 ESC 電源線會判極性，XT60 有防呆不判 |
