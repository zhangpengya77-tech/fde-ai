## 二、完成功能

### 1. 待複核排序（四項，含穩定次要鍵）

| 值 | 標籤 | 主鍵 | 次要鍵（穩定） |
|----|------|------|----------------|
| `oldest`（預設） | 提交時間：最早優先 | submitted_at 升序 | 學員名稱 → 紀錄編號 |
| `newest` | 提交時間：最新優先 | submitted_at 降序 | 學員名稱 → 紀錄編號 |
| `student_asc` | 學員名稱 A→Z | 學員名稱 | 紀錄編號 → 提交時間 |
| `record_asc` | 紀錄編號由小到大 | 紀錄編號（R 群先於 M 群、群內數字升序） | 學員名稱 → 提交時間 |

- 任意兩列皆有**全序**：相同名稱、相同時間都不會造成順序不固定（同一請求重複執行結果一致，已由測試固定）。
- **提交時間缺失者，在四種排序方向下一律排最後**（以 aware 下限值作鍵，避免 naive/aware 比較錯誤）。
- 排序只改變呈現順序，不動任何統計、權限或資料。

### 2. 待複核清單篩選（三項＋班級）

| 篩選 | 參數 | 選項 | 說明 |
|------|------|------|------|
| 班級 | `cohort` | 教師授權班級 | **沿用頁面既有「班級選擇」**（P4 已具備），未重複建造第二個班級篩選；結果只來自教師有權限的班級 |
| 成長紀錄 | `p_record` | 全部紀錄 / R01–R08 | 成長紀錄依自身槽位比對 |
| 成果類型 | `p_type` | 全部類型 / 成長紀錄 / 任務提交 | 依項目種類過濾 |
| 待複核狀態 | `p_status` | 全部 / 待教師複核 / 需要補充 | 預設「全部」＝submitted＋needs_revision |

- **任務提交不強制歸類**：任務只有在 P2 權威對應表（`TASK_RECORD_MAP` / `TASK_RELATED_RECORDS`）確實對應某 R 槽位時，才會出現在該槽位的紀錄篩選中；**沒有對應 R 槽位的任務（如 T10）在任何 R 篩選下都不會出現**（測試已固定）。
- **狀態維度不強加於任務**：任務進度僅有 `submitted` 一態（模型無 needs_revision），因此選擇「需要補充」時任務不會被硬塞進該狀態。
- 篩選無結果時顯示「沒有符合目前篩選條件的待複核成果。」（與「目前沒有待複核的成果。」區分）。
- 清單標題在篩選生效時附註「目前篩選顯示 N 項」；**四張統計卡片固定為班級層級 P4 語意（待複核成果＝待教師複核數），不隨篩選變動**（DEMO 已驗證）。

### 3. 學員進度篩選

- `s_state`：`全部學員`（預設）／`尚未提交任何 R01–R08`（已提交數 0 者）。
- 篩選無結果時顯示「沒有符合篩選條件的學員。」（與「此班級目前尚無在學學員。」區分）。
- 截斷處已註明，其餘選項待教師補示（結構上新增一個選項即為一行）。

### 4. 條件共存與參數保留

- 頁面上三個控制列（班級／待複核／進度）各自以**隱藏欄位攜帶其他表單的有效條件**，切換任一條件時其餘條件全部保留（例：切換排序不會遺失紀錄／類型／狀態／進度篩選）。
- 非法值一律安全回落（`sort`→oldest、`p_record`→全部、`p_type`→全部、`p_status`→全部、`s_state`→全部），不報錯、不縮減非預期範圍。
