# 俯仰／橫滾（pitch / roll）通道檢查表

> 適用範圍：只處理「右搖桿上下＝俯仰、右搖桿左右＝橫滾」這兩條通道。
> 偏航、油門、飛行物理與既有標定檔都不在此頁範圍內。

---

## 0. 先確認「瀏覽器真的看得到搖桿」

模擬器只認 **USB HID 搖桿**。藍牙連線（Windows 顯示 `ExpressLRS Joystick`）雖然配對成功，
但不會產生 game-controller 集合，瀏覽器的 Gamepad API 讀不到，畫面會一直顯示「遙控器未連接」。

| 連線方式 | 瀏覽器可讀 | 說明 |
|---|---|---|
| USB + 選單選 `USB Joystick (HID)` | ✅ | 唯一可用路徑，裝置 ID `VID_1209 / PID_4F54` |
| USB + 選 `USB Storage` 或 `USB Serial` | ❌ | 只會出現磁碟機或 COM 埠，沒有搖桿 |
| 藍牙（BLE） | ❌ | Windows 有裝置、瀏覽器 0 個 pad |

---

## 1. USB 接線與選單

1. 用**資料線**（不是純充電線）把遙控器接到電腦 USB 埠。
2. 遙控器開機後螢幕會跳出 USB 連線選單，選 **`USB Joystick (HID)`**。
   - 若沒跳選單：進 `SYS` → `硬體`／`USB 模式`，把 USB 模式改成 Joystick。
3. 電腦端確認（可略）：
   ```
   Get-PnpDevice -PresentOnly | ? InstanceId -match 'VID_1209'
   ```
   應出現 `HID-compliant game controller`，且 `Present=True`。
4. 插上後**晃一下右搖桿**：Chrome 要有輸入才會把裝置「叫醒」曝光給網頁。

## 2. 開哪個網址

```
http://192.168.1.114:8111/sim/
```

### 2.1 先把伺服器開起來（雙擊即可）

在專案根目錄 **雙擊 `start-8111.bat`**。它會：

1. 自動清掉仍佔用 8111 的舊伺服器程序（避免兩個程序搶同一個埠，導致頁面時好時壞）。
2. 以 `--lan` 啟動，並在視窗裡印出：
   ```
   FDE teaching server on http://0.0.0.0:8111/sim/
     teacher URL: http://192.168.1.114:8111/sim/
     latest profile: ...\fde-rc-calibration-....json
     keep this window OPEN while teaching; close it (or Ctrl+C) to stop the server.
   ```
3. **這個黑色視窗要一直開著**，關掉就等於關掉伺服器（瀏覽器會出現 `ERR_CONNECTION_REFUSED`）。

> `ERR_CONNECTION_REFUSED`／「無法訪問此網站」＝伺服器沒在跑，先重新雙擊 `start-8111.bat`，
> 再看視窗裡印的 teacher URL 是否與瀏覽器網址一致。
>
> 若看到 **404 · 找不到這個網址**：網址本身錯了（不是伺服器問題）。常見三種：
> ① 用了帶隨機檔名或 `?sig=` 參數的**暫存／預覽連結**；
> ② 漏打 `http://`，瀏覽器把它當成 `/sim/` 底下的相對路徑（變成 `/sim/127.0.0.1:8110/...`）；
> ③ 多打了 `/index.html` 以外的路徑。**一律回到 `http://192.168.1.114:8111/sim/`**，
> 或直接點 404 頁面上的藍色按鈕。

- **全程用同一個網址**。IndexedDB 是「按來源（origin）分開存」的，換網址等於換一個資料庫，
  會看到另一份（可能是舊的）標定。
- 服務端預設只綁 **127.0.0.1**（安全預設）。要讓區網其他裝置連線，需以
  `python tools/serve-8111.py --lan` 啟動（`start-8111.bat` 已帶此參數）；啟動時會印出警告——
  **只有受信任的教學網路才用 --lan**，因為它同時開放 `POST /api/rc/captures`（可寫入標定檔）。
- 標定面板在畫面**下方中間**（步驟編號 `03 遙控器`）。面板很窄，按右上角
  **「放大面板」** 會展開成大片可讀視窗。

## 2.5 「鏈路」診斷（推桿時一眼看出哪一層出錯）

畫面右上角的遙控器 HUD，四軸數值下方多了一個 **鏈路** 區塊：

```
鏈路      raw     norm    cmd     位移 前/右
Pitch a1  +0.98   +1.00   +1.00   前 +8.00
Roll  a0  +0.01   +0.00   +0.00   右 +0.00
```

四欄就是一條完整路徑：**原始值 → 歸一化值 → 飛行指令 → 機身座標的實際速度**
（「前」= 沿機頭，「右」= 機身右側，單位 m/s）。底下那行字會直接指出出錯的層：

| 畫面文字 | 意思 | 該做什麼 |
|---|---|---|
| `歸一化層：… raw +0.98 卻得到 norm +0.00` | 通道綁錯（source 指到別的軸）或死區太大 | 用引導式標定重綁 source |
| `映射層：… norm 與 cmd 反向` | reverse 或映射寫反 | 檢查該軸的「反向」勾選 |
| `飛控層：cmd +1.00 但機體沿機頭/右側的分量是 −8.00` | 指令對、機體卻走反 → 航向旋轉算錯 | 這是程式問題，回報 |
| `鏈路正常：Pitch cmd +1.00，機體沿機頭 +8.00` | 整條路徑都對 | — |

> 這一欄是「用機身座標」而不是世界座標判讀，所以**任何航向下都成立**：
> 先打偏航讓機頭轉 90°，再前推，位移欄仍應顯示「前 +8.00」而不是「右 +8.00」。

### 視角也一起改了（追尾視角）

原本相機固定在機體的 +X/+Z 斜後方（世界座標 `(12, 8, 15)`），所以世界 −Z（機頭）
在畫面上是「右上斜向」——**前推看起來就像橫向移動**，而且航向一變，畫面方向與
機身方向就完全對不上。現在相機永遠在**機頭正後方**：

- 螢幕上方 = 機頭方向，螢幕右方 = 機身右側
- 打偏航時世界會繞著機體轉（這是正常的，代表相機跟著機頭走）
- 上方座標列多了 **航向 XX°**，可以對照機頭到底轉到哪

## 3. 怎麼用「搖桿軸向快速測試」

位置：放大後的標定面板 → **「搖桿軸向快速測試（僅 pitch / roll）」**。

**目前生效映射（2026-10-22 真機實測修正）**：

| 功能 | 通道 | 反向 | 實測依據 |
|---|---|---|---|
| Roll（右桿左右） | axis0 | 否（reverse=false） | 右打為正、峰值 1.000（已驗證，不再動） |
| Pitch（右桿上下） | axis1 | 否（reverse=false） | 軸向探針 `fde-stick-axis-probe-2026-10-22T00-08-20-141Z.json`：右桿上推原始值 **+0.984** |
| Yaw（左桿左右） | axis3 | 否 | 既有實測，不動 |
| Throttle（左桿上下） | axis2 | 否（unipolar） | 既有實測，不動 |

> 2026-10-22 真機實測 axis1 推上為正，歷史紀錄 -1 已不適用：早期 live probe 與
> 2026-10-21 `pitchroll-restore` 檔把「上推」記成 -1，pitch 因此一直帶 `reverse=true`，
> 結果前推變後退。本次只把 pitch 的 reverse 由 true 改成 false，其餘一律不動。
> 舊檔已備份到 `fde-rc-calibration-backup/`。

1. 先確認上方「即時通道」的數字靜止不動（搖桿放開、油門不動）。
2. 按 **「開始測試」**（右桿上下那一列）。
3. **只把右搖桿往上推到最上**，保持約一秒，然後**放開回中**。
4. 放開後結果自動出現，一行字包含：軸號、符號、峰值、目前映射、結論。
5. 換 **「右桿左右」** 那一列，重複：只往右推到最底，保持一秒，放開。
6. 兩項都測完後按 **「匯出測試結果 JSON」**，把檔案內容貼回來。

> 這個工具**只記錄、不套用**。它不會改 source、不會翻 reverse、不會寫任何標定檔。
> 峰值低於 **0.5** 一律判「結論無效」，不會再給「綁錯／正確」這類不可靠的結論。

判定文字的長相（範例，對應 2026-10-22 修正後的映射）：

```
右桿上下 = axis1，推上為正（峰值 0.982）→ 目前映射 pitch←a1，正確（歸一化 +1.00，機頭下壓、向前飛）
右桿上下 = axis0，推上為正（峰值 0.983）→ source 綁錯：pitch 目前綁 axis1，建議改 pitch←a0（reverse=false）
右桿上下 = axis1，推上為負（峰值 0.982）→ 方向反：目前 pitch←a1，推滿卻得到歸一化 -0.98（應為 +1），建議翻 reverse（改為 reverse=true）
右桿上下 = axis1，推上為正（峰值 0.079）→ 推動幅度不足，結論無效：請把搖桿推到底再測一次
```

## 4. 快速測試推不滿時：改用「原始軸連續錄製」

如果右桿上下只能推到峰值 0.07～0.08，快速測試與引導式標定都會失效（這就是 10-22 遇到的狀況）。
改用錄製：它**不要求你推滿單一次**，而是記錄整段時間每個軸的原始值。

1. 放大面板 → **「原始軸連續錄製（10 秒）」** → 按 **「錄製 10 秒」**。
2. 依提示把右桿**依序畫圈：上 → 右 → 下 → 左**，每個方向停約 1 秒、**幅度盡量推到底**。
   - 先按錄製、放開搖桿，**再開始畫**（前幾幀要是靜止，系統才知道基準）。
3. 錄完會自動出現兩段資訊：
   - 各軸 `min / max / 平均 / 起始 / 結束 / 變化量` 排序；
   - **錄製建議**：右桿上下對到哪個軸、右桿左右對到哪個軸，以及建議的 source / reverse。
4. 兩組峰值都 ≥ **0.70** 且不是同一軸時，才會出現 **「套用建議」** 按鈕；
   否則會顯示「請推到底重錄」，此時按了也不會寫入任何東西。
5. 按 **「匯出錄製 JSON」** 把結果貼回來（JSON 裡已含建議，方便核對）。

> 「套用建議」只會改寫**與建議不一致**的通道。已經實測正確的通道（例如已驗證的
> `roll ← axis0 / reverse=false`）完全不會被碰到；偏航、油門、死區、expo 一律不動。

---

## 5. 套用建議之後：方向驗收

放大面板 → **「方向驗收（右桿 pitch / roll）」**。先**解鎖並起飛**（驗收需要飛行狀態），
然後三項各按一次「開始測試」：

| 項目 | 動作 | 綠燈條件 |
|---|---|---|
| 右桿前推（Pitch） | 右桿向前推到底保持 | `Pitch` 為正 **且** 機體真的前進 |
| 右桿右打（Roll） | 右桿向右打到底保持 | `Roll` 為正 **且** 機體真的右移 |
| 放開（停止） | 放開所有搖桿 | 1.2 秒內殘速 < 0.1 m/s（位移停止） |

每項會顯示綠燈通過或紅燈失敗，並附上實測數字（例如 `Pitch +1.00、前進速度 4.02 m/s`）。
三項跑完按 **「匯出驗收結果 JSON」** 貼回來。紅燈時的提示會直接指出是方向反（翻 reverse）
還是機體沒動（先確認已在飛行狀態）。

## 6. 靜止漂移（放開搖桿卻一直飄）

放大面板 → **「漂移診斷（靜止時）」**：

- 四個功能各顯示**靜止原始值**與**歸一化值**。歸一化不為 0 就是漂移來源。
- 若自回中軸（roll / pitch / yaw）**停著卻偏離中心**，會出現
  「偵測到搖桿中心偏移…請按『校正中心』」→ 按下去**只更新 center**，
  不動 source / reverse；寫入後立即生效並存到本機。
- **「重設位置」**：立刻把機體位置與速度清零回到 Home（暫時止血，不改物理）。
- 飛控本身已在**無輸入時**把殘速以 0.3 秒時間常數指數衰減到 0，放開後不再無限滑行。

## 7. 四種結論怎麼處理

| 結論 | 意思 | 怎麼改 | 改哪裡 |
|---|---|---|---|
| **正確** | 軸與方向都對 | 不用改 | — |
| **source 綁錯** | 你推的那根桿，動到的不是目前綁定的軸 | 把該功能的**通道**改成建議的 axis | 面板「通道」下拉選單 |
| **方向反** | 軸對，但推滿得到負值 | 勾／取消該功能的**「反向」** | 面板「反向」勾選框 |
| **無法判定** | 沒動、只推一半、或尚未載入標定 | 推到底重測；或改用「錄製 10 秒」 | — |

規則：

- **source 綁錯 ≠ 方向反**。軸綁錯時翻 reverse 只會讓錯的軸反向，永遠調不出正確手感。
- **一次只改一處**（先改 source，重測；再判斷要不要翻 reverse），不要同時改兩層。
- 改完在面板按 **「保存標定」** 才會落庫；保存後 HUD 的「來源」會變成「手動儲存（本機）」。
- 若 HUD 顯示 **⚠ 與擷取檔映射不同**，代表本機這份和伺服器上的最新擷取檔不一致：
  想改用擷取檔就按「清除本機標定並重新載入」。

## 8. 常見狀況

- **插上卻沒反應**：先晃搖桿喚醒；仍無效就拔插一次 USB，確認選的是 `USB Joystick (HID)`。
- **瀏覽器顯示 `ERR_CONNECTION_REFUSED`／「無法訪問此網站」**：伺服器沒在跑。雙擊 `start-8111.bat`，
  確認黑視窗還開著、裡面印的 teacher URL 與瀏覽器網址一致。若視窗一開就關，多半是
  「port 8111 is already in use」——把佔用的舊視窗關掉再啟動（腳本會自動嘗試清掉）。
- **頁面時好時壞、偶爾連不上**：可能有兩個程序同時佔用 8111（Windows 允許重複綁埠）。
  在 `cmd` 執行 `netstat -ano | findstr :8111`，若看到兩行 `LISTENING`，把較舊的 PID
  `taskkill /f /pid <PID>` 掉，或直接重新雙擊 `start-8111.bat`。
- **改了原始碼但畫面沒變**：先 `npm run build` 重建 `dist`，再 `Ctrl + Shift + R` 硬刷新；
  伺服器只讀 `dist`，不會即時編譯。
- **用幾分鐘後掉線**：Chrome 對閒置的 Gamepad 會隱藏裝置，晃一下搖桿即可恢復，不需重開頁面。
- **結果和上次不一樣**：確認網址沒變（IndexedDB 按 origin 分開），並看 HUD 的「來源／檔名」是不是同一份。
- **頁面全白**：先 `Ctrl + Shift + R` 硬刷新（舊 HTML 快取指向已不存在的舊 JS 就會白屏）。
- **想留下證據**：除了「匯出測試結果 JSON」，面板也有「下載測量記錄」，會帶出各軸休止值與極值。
