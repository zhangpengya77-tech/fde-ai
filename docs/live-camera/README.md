# 即時鏡頭檢測：使用說明、已知限制、驗證清單

分支：`feature/live-camera`（工作樹 `D:\FDE-AI-UAS-v2.0-live-camera`，從正式站 `2e7f9f3` 分出）
狀態：預覽中，尚未 commit、尚未部署。

## 一、學員怎麼用

1. 登入學員帳號 → 「鷹眼 AI 檢測中心」→「F450 槳葉正反及方向檢查」。
2. 上方有兩個分頁：
   - **圖片上傳**：和原本一樣上傳照片。現在照片上會疊綠框（對）、紅框（錯）、灰框（無法判斷）。
   - **即時鏡頭**：按「開始鏡頭檢測」，允許相機權限。
3. 俯視、機頭朝上，讓四支槳完整入鏡，拿穩約 1～2 秒（8 幀中要有 5 幀一致）。
4. 畫面下方的答案面板會安靜地顯示結果：
   - 綠色：「目前四支槳都已換到正確位置。」
   - 紅色：逐位置說明，例如「左上應為 CW，目前是 CCW，請依正確方向更換。」
   - 灰色：「我無法判斷，請找線下老師確認。」
   - 先錯後改對：「你已經換到正確的了。」
5. **要聽 AI 助教回答時才發問**：可以打字，或按「🎤 用說的」。系統會依目前結果回答對錯和正確裝法，並朗讀出來；答錯時會附上一次知識庫補充。
6. 手機預設用後置鏡頭；「切換鏡頭」可以換鏡頭；「省電模式」會降低鏡頭解析度和更新頻率。
7. 鏡頭畫面只在裝置上辨識，不會上傳。

## 二、老師要知道的

- **只會用老師已啟用（ACTIVE）的槳葉模型**。老師在視覺中心撤下或封存模型後，即時鏡頭會立刻改顯示「老師尚未啟用槳葉辨識模型」。
- **模型要先轉成瀏覽器用的格式**：每次啟用新模型後，要在模型目錄產生 `best.onnx` 和 `best.onnx.json`。
  - 工具：`live_backend/tools/export_prop_live_onnx.py`
  - 必須用另外建立、裝有 `onnx` 套件的 Python 執行，不要裝進正式站的 Python。
  - 沒有轉檔時，即時鏡頭會顯示「目前沒有可用的槳葉辨識模型」。
- **判定規則都在 `src/prop-live/prop-judge-rules.json`**：版面、期望類別、信心門檻 0.5、重疊門檻、穩定幀數 8 取 5、推論尺寸 640、FPS 上限，改規則不用改程式。
- **畫面文字都在 `src/prop-live/prop-live.zh-TW.json`**。

## 三、已知限制

1. **速度**：這台開發筆電（Intel 內顯）實測，WebGPU 每秒約 3.3～7.0 次判定（Playwright 測試約 3.3，預覽網址實測約 6.6～7.0），WASM 約 1 次，都沒有達到每秒 8～15 次的目標。手機和獨立顯示卡的速度還沒實測。
2. **常出現「無法判斷」**：15 張固定測試照片中，9 張判為無法判斷（多數是信心不足）。這是「寧可無法判斷，也不亂判斷」的代價；判為對或錯的 6 張全部與人工標註一致。
3. **416 低解析度不採用**：實測 416 的判定只有 6/15 和 640 一致，還出現一張給錯指示，所以手機也固定用 640。
4. **前鏡頭會鏡像**：用前鏡頭時可能判為「四支全反」並提醒確認鏡像。建議用後置鏡頭。
5. **iPhone 需要 iOS 16.4 以上**；沒有 WebGPU 的裝置會改用 WASM，速度較慢。
6. **第一次使用要下載約 33 MB**：模型 11 MB，推論程式 22 MB。建議在 Wi-Fi 下使用。
7. **AI 助教的「拍照問答」還沒改**：`coach_prop_check.py` 仍用舊規則（以畫面正中央分四格），和這裡的判定可能不一致。這次範圍沒有改它。
8. **圖片上傳的判定方式改了**：象限改用四框的重心劃分，機身不在畫面正中央的照片，結果可能和原本不同（這是刻意的改變）。

## 四、預覽環境

- 啟動：雙擊 `ops/live-camera-preview/start_preview.bat`，或在 Git Bash 執行 `start_preview.sh`。視窗要保持開著；關閉就會停止。
- 預覽網址是臨時通道，每次啟動都會換。網址會顯示在視窗裡，也會寫進 `D:\FDE-AI-Runtime\v2-live-camera\public_host.txt`。
- 預覽環境在 `D:\FDE-AI-Runtime\v2-live-camera`：
  - 資料是正式資料庫的快照，可以用正式帳號登入；在預覽環境做的任何事都不會回寫正式站。
  - 金鑰、埠號（844x／8843）都和正式站分開。
  - 知識庫 8772 和飛行健康 8040 共用正式站的唯讀服務。
- 重新建立預覽資料：執行 `python ops/live-camera-preview/setup_preview.py --refresh-data`，再重新轉一次 ONNX。
- 停止預覽：關閉啟動視窗；如果埠號仍被占用，執行 `ops/live-camera-preview/stop_preview.ps1`。它只會停止預覽專用的程序，不會影響正式站。
- 預覽資料庫裡另外建了一個預覽專用測試學員 `preview-livecam@preview.local`，用來驗證閘道。這個帳號沒有可用密碼、無法登入，而且只存在於預覽環境的資料庫複本。

## 六、部署（等你說「驗證通過，部署」之後才做）

1. 備份正式站目前版本：git 標籤，加上 `index.html`、`src/` 的副本。
2. 在正式模型目錄用獨立 Python 轉出 `best.onnx` 和 `best.onnx.json`（不安裝套件到正式站 Python）。
3. 合併 `feature/live-camera` 到正式站分支，重新啟動 Live 服務以載入新端點。
4. 部署後冒煙測試：三個入口都能打開（圖片上傳、即時鏡頭、電力巡檢），新端點沒登入時回 403。
5. 提供一鍵回滾：切回備份標籤，並刪除這次加入的 ONNX 檔。
