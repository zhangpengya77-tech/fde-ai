## S1 連線與車輛狀態

1. 使用者選擇「真機」或「仿真」，兩個按鈕顏色不同，選完後頁面頂部常駐模式色條。
2. **真機**：按「選擇 USB 裝置」→ 瀏覽器跳出系統授權視窗 → 使用者手動選 COM 埠 → 選 Baud Rate（預設 115200）→ 連線。每次都要手動選，不記住授權、不自動連線。
3. **仿真**：按「連線仿真」→ 網站向後端申請唯讀 ticket → 連上 Gateway。
4. 收到第一個 HEARTBEAT 後，顯示飛控類型、韌體版本、System ID／Component ID。
5. 錯誤一律用白話說明。例如 COM 埠被占用時顯示：「這個 USB 連線正被其他地面站使用，請先關閉 Mission Planner 或 QGC，再按重新連線」，**不自動重試**。
6. 超過 3 秒沒收到 HEARTBEAT，狀態變黃色「訊號中斷」；超過 10 秒變紅色「已斷線」，並停用所有寫入功能。

## S2 飛行視圖

- 顯示：飛行模式、ARM 狀態、電池電壓／電流／剩餘、GPS 定位類型與衛星數、高度、Roll／Pitch／Yaw、HEARTBEAT 狀態、最後一次遙測更新時間。
- 每個數值旁邊標註資料來源訊息（例如 `ATTITUDE`、`SYS_STATUS`）。超過 2 秒沒更新的數值變灰，不保留舊值假裝最新。
- 真機模式**沒有**任何控制按鈕（ARM、模式切換、起飛、返航都沒有）。
- 仿真模式只有拿到控制 ticket 時，才顯示 AUTO／RTL 按鈕。

## S3 航線規劃（仿真）

1. 在地圖上點擊新增航點，可以拖曳調整，在清單裡修改高度和順序。
2. 任務固定以 TAKEOFF 開頭、RETURN_TO_LAUNCH 結尾，少了就提示補上。這是 SITL 測試中實際遇到的問題（AUTO 模式 init failed）。
3. 航線可以存成檔案、從檔案載入；只保存在學員自己的課程資料裡。
4. 「上傳到仿真」和「開始任務」需要控制 ticket；上傳後讀回比對航點數量和內容。
5. 任務執行中顯示目前航點序號；結束時記錄完成時間、是否觸發返航，存成任務結果。

## S4 參數與設定

1. 連線後按「讀取全部參數」，顯示進度（已收到／總數）。逾時的參數自動補讀，最多重試 3 次，仍缺少的列出清單。
2. 依群組分類（例如 `ATC_`、`PSC_`、`BATT_`），可以搜尋。
3. 顯示「讀取時的原始值」和「目前值」，有差異的標示出來。
4. 匯出參數檔和差異報告，學員可以主動上傳到課程紀錄。
5. **寫入**（P3）只在白名單內的參數顯示編輯功能，並且依序檢查：Disarmed → 連線有效 → 在白名單內 → 已勾選「已拆槳、已斷電池」→ 顯示原值與新值並二次確認 → 發送後等待回覆並讀回 → 記錄結果。
6. AI 調參助教只顯示說明和建議，**沒有**「套用建議」按鈕；寫入一律走上面的流程，並需要教師批准。
