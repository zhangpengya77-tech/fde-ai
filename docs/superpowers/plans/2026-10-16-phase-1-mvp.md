# FDE Power Inspection Simulator Phase 1 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build one complete offline teaching loop in which a learner flies an F450 by keyboard or USB controller, inspects one transmission-line target, takes evidence, receives clearly labelled simulated AI feedback and a saved score report.

**Architecture:** A Vite/TypeScript/Three.js application keeps input, flight, scene, mission, inspection, scoring and persistence behind focused TypeScript interfaces. Phase 1 first proves one transmission-line scene; later scenes reuse those interfaces and are not part of the initial loop.

**Tech Stack:** Vite, TypeScript, Three.js, Vitest, Playwright, IndexedDB, Canvas 2D.

**Spec:** `docs/superpowers/specs/2026-10-16-power-inspection-simulator-v1-design.md`

## Global Constraints

- Work only in `D:\FDE-Power-Inspection-Simulator`; existing FDE projects and source assets are read-only.
- Use Vite + TypeScript + Three.js without React, ROS, PX4, ArduPilot WASM, Docker or a server database.
- Keep the flight core independent from controller brands through `PilotInputAdapter`, `InputNormalizer` and `ChannelMapper`.
- Keep all runtime assets local after dependency installation; no application-time public network dependency.
- Copy `F450_Assembly.glb` only after visual, structure and license checks; always retain a programmatic F450 fallback.
- Label `MockInspectionAI` output as simulated and never present it as YOLO.
- Add each third-party dependency or copied asset to `THIRD_PARTY_NOTICES.md`.
- Run targeted tests after every task and retain test evidence and screenshots.

## Review Focus

- WebGL unavailable or GLB load failure must show the programmatic F450 fallback and a clear non-blocking message; Task 2 browser tests cover this.
- Input disconnection or stale data over 250 ms must enter hover without forcing throttle to zero; Task 3 unit and browser tests cover this.
- A learner must not complete an inspection merely by approaching it; Task 5 tests require a valid photo and assessment.
- Continuous proximity to one hazard must create one event until the aircraft exits and re-enters; Task 4 and Task 6 tests cover this.
- IndexedDB failure or refresh must not silently lose the current report; Task 7 tests cover recovery and JSON fallback.
